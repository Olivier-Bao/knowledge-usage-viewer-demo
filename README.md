# Knowledge Usage Viewer｜大模型知识使用研究工作台

把模型生成、固定回答分析、Token 与组件信号阅读、人工标注及导出组织成一个可追溯的研究流程。

## 当前公开范围

研发版已有 FastAPI + SQLite + 原生 JavaScript 工作台，并有接入 Qwen3-8B 和定制 Transformers 引擎的 V1.0 发布记录。公开版目前仅包含设计说明与离线信号契约示例；完整 UI、研究引擎和模型不在此仓库。

本仓库首版整理于 **2026-11-10**。`demo.py` 和 `sample.json` 是本次公开展示新编写的最小示例，经 AI 辅助生成和本地执行检查，不是历史项目源码的完整抽取，也不代表历史实验结果。仓库不要求 API Key、GPU 或第三方 Python 包。

## 一分钟运行

```bash
python demo.py
python demo.py --self-test
```

要求 Python 3.10+。正常输出包含 `valid: true`、`data_kind: synthetic`；自检覆盖正常记录和四类错误，成功时显示 `5 checks passed`。示例只处理随仓库提供的固定结构；不是面向任意外部 JSON 的完备输入校验服务。

校验一个合成信号记录：目标 Token、来源引用、组件信号维度与有限数值。输出只证明数据契约检查可运行，不证明归因算法有效。

## 研发架构与设计取舍

下图描述研发项目的职责划分，不表示全部代码已在公开版提供。

```text
输入与来源标记 → API 与任务接纳 → 后台 worker → 引擎适配器 → 模型计算
                         ↓                          ↓
                    SQLite 对象版本 ← 文件产物与研究导出
```

- 输入快照与任务身份绑定，避免旧任务结果迟到后污染当前研究对象；取消请求与计算资源释放分别处理。
- 采用单用户、有界推理任务架构，优先满足研究工作流；不把单 worker 描述为高并发服务。
- 保留信号原值，显示变换与研究数据分离；来源相关贡献值不是幻觉概率，也不是内外知识真实占比。
- AI 辅助开发以需求、契约、任务和验收组织；曾遇到原型与实现版本脱节，后续把完整用户流程与实际页面对照纳入验收。

以明确输入输出约束任务；核查生成代码；用正常与失败样例验证；保留结果与未完成项。代码测试、产品流程验收与科学评价分别记录，不用测试通过率替代模型效果。
